# 数据结构 AI 助教项目总结报告

## 一、项目概述

本项目基于 Open WebUI 构建课程专属“数据结构 AI 助教”。系统以本地 Ollama 模型为语言能力底座，以分类课程资料为 RAG 知识来源，以结构化真题题库和 Python Workspace Tool 提供真实可执行的抽题、判分、检索、统计和先修关系查询。目标是让学生获得有出处、可追溯、不过度代做的课程辅导。

## 二、需求完成情况

1. 系统部署：提供 Docker Compose，包含 Open WebUI、Ollama 和自动模型拉取服务；默认连接 `qwen3:4b`。
2. 课程知识库：27 份 Markdown，包含 17 份历年试题、6 份分章讲义、2 份实验指导、示例代码与常见错误说明，超过 8 文件且覆盖至少 3 类资料。
3. 课程 AI 助教：系统提示词定义身份、范围、分层回答、引用、不确定处理、学术诚信、作业引导和输出格式。
4. 自定义扩展：实现 5 个结构化工具能力，不依赖提示词模拟。
5. 测试评价：提供 15 项验收矩阵，覆盖题目规定的全部类别，并提供基线/优化提示词和量化对比指标。

## 三、数据与知识库

教师提供的压缩包包含 2009–2025 年数据结构试题及整理数据。本项目抽取并保留 218 道结构化题目，其中客观题 184 道、综合题 34 道。题库按年份、章节、考点、难度和题型组织。

为避免知识库只有真题、缺少教学解释，项目补充了线性表、栈队列数组、树、图、查找、排序六章讲义，两份综合实验指导，以及 C++ 示例代码和常见错误说明。上传时保持 `lectures`、`labs`、`examples`、`exams` 分类，便于检索与引用。

## 四、自定义工具实现

`data_structures_question_bank.py` 按 Open WebUI Workspace Tool 规范定义带类型注解的方法和可配置 Valves：

- `random_questions`：多条件筛选、可复现随机抽题、控制是否显示答案。
- `grade_objective_answer`：精确匹配客观题答案，返回解析和来源。
- `search_questions`：在题干、考点和选项中检索。
- `chapter_statistics`：返回章节、题型、难度和年份统计。
- `prerequisite_path`：返回常见知识点的建议先修路径。

安全方面，题库以只读卷挂载；工具不联网、不写文件、不执行命令；返回数量有限制；异常参数返回结构化错误。综合题因缺少完整权威答案而拒绝自动判分，避免产生虚假评分。

## 五、提示词与 RAG 优化

基线提示词只有身份和一般任务描述，容易出现不检索、无引用、资料缺失时猜测以及直接给出作业答案等问题。优化版增加：

- 先检索再回答，指定语义检索与精确检索的选择方式。
- 结论就近标注文件、章节或工具来源。
- 查无资料时固定披露不确定性并请求缺失信息。
- 练习和判分任务必须调用结构化工具。
- 默认采用“结论—解释—依据—自测提示”格式。
- 根据学生水平调整解释深度。
- 对作业给提示与分步指导，对综合题只做形成性反馈。

## 六、测试结果

离线自动测试结果：12 项工具单元测试全部通过；数据质量检查通过；Compose 配置解析通过。确认题目 ID 唯一、客观题均有合法选项与答案、难度取值合法、知识文件数和分类满足要求。

受当前构建主机环境限制，Docker 命令行存在但服务未运行，且未找到 Docker Desktop 可执行程序，因此本次无法生成可信的 Open WebUI 大模型实际输出。项目没有把预期回答伪装成实测结果。部署后应按验收矩阵运行 15 项对话测试并保存截图/对话导出，再完成基线与优化版量化对比。

## 七、局限与改进方向

- 图形题的文字化资料可能缺少原图，后续应上传原始 PDF 或题图并启用可靠 OCR。
- 小型本地模型的工具选择能力有限，可换更强模型或细化少样例提示。
- 可增加教师评分规则，使综合题反馈更接近课程标准，但在没有教师标准前不应自动给分。
- 可使用 Open WebUI API 自动同步知识库和导出测试对话，减少人工部署步骤。
- 课程讲义为项目整理版，最终应由任课教师审核术语、章节边界和引用格式。
