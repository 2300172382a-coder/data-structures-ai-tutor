# 数据结构 AI 助教项目总结报告

## 一、项目概述

本项目基于 Open WebUI 构建课程专属“数据结构 AI 助教”。系统在 Windows 上以 Open WebUI 0.11.3、llama-server 和 Qwen2.5-3B-Instruct 本地运行，通过课程知识库完成检索增强问答，并通过真实 Workspace Tool 执行抽题、客观题批改、题库检索、覆盖统计和先修关系查询。

项目的核心目标是：回答有课程依据、来源可追溯；资料不足时明确说明不确定；根据问题难度调整解释；能够练习与反馈，同时遵守“不直接代做整份作业”的学术诚信边界。

## 二、Docker 是否必要

题目要求“部署 Open WebUI 并连接至少一个大模型”，没有限定容器技术，因此 Docker 不是硬性要求。本项目已经用 Windows 原生方式完成实际部署和全部验收：

- 模型服务：llama-server，监听 `127.0.0.1:11435`，使用单槽 16384-token 上下文；
- 本地模型：Qwen2.5-3B-Instruct GGUF；
- Web 服务：Open WebUI 0.11.3，监听 `127.0.0.1:3000`；
- 启停脚本：`scripts/start-native.ps1`、`scripts/stop-native.ps1`；
- 初始化脚本：`scripts/setup-native.ps1`、`scripts/bootstrap_openwebui.py`。

项目仍保留 `docker-compose.yml` 作为跨平台备选，但提交、演示和验收都不依赖 Docker。

## 三、需求完成情况

1. **系统部署**：Open WebUI 已连接本地 Qwen2.5-3B 模型，并创建可直接选择的课程模型 `data-structures-ai-tutor`。
2. **课程知识库**：共 28 份文件，分为历年试题、分章讲义、实验指导、示例与辨析四类，超过题目规定的 8 文件和 3 种类型。
3. **课程助教行为**：系统提示词覆盖身份、范围、不同水平解释、代码与复杂度、练习、批改、引用、资料缺失、课程越界和学术诚信。
4. **真实自定义扩展**：实现一个可由 Open WebUI 对话实际调用的 Python Workspace Tool，内含 5 个函数，不以提示词模拟工具结果。
5. **测试与对比**：完成 15 项实际 API 验收并保留模型输出、来源和工具返回；另外对 5 项代表性问题完成优化前后对比。
6. **工程交付**：包含源码、部署文档、需求映射、Codex 交互记录、测试报告、分阶段 Git 提交、可克隆的 Git bundle，以及公开 GitHub 仓库 <https://github.com/2300172382a-coder/data-structures-ai-tutor>。

逐条证据见 `docs/REQUIREMENT_CHECKLIST.md`。

## 四、数据与分层知识库

教师资料覆盖 2009–2025 年试题。项目整理出 218 道结构化题目，其中客观题 184 道、综合题 34 道，并保留年份、章节、考点、难度、选项、答案、解析和来源等字段。

Open WebUI 中建立两层知识库：

- **完整归档库（28 份）**：17 份历年试题、6 份讲义、2 份实验指导、3 份示例/常见错误/辨析资料，用于满足完整课程资料归档和人工查阅；
- **教学核心库（11 份）**：不直接挂载历年试题，优先提供讲义、实验和示例，作为课程模型默认 RAG 来源。

之所以采用分层设计，是因为完整库中大量真题关键词密度高，容易压过概念讲解。默认检索核心库后，概念题、算法对比和错误分析的来源更稳定；需要精确真题时再调用结构化题库工具。RAG 使用混合检索，最终参数保存在 `config/rag-config.json`。

## 五、自定义工具实现

`openwebui-tools/data_structures_question_bank.py` 提供以下函数：

- `random_questions`：按章节、难度、题型抽题，支持固定随机种子和隐藏答案；
- `grade_objective_answer`：按题目 ID 判分，返回正确答案、解析和来源；
- `search_questions`：检索题干、考点和选项；
- `chapter_statistics`：返回章节、题型、难度、年份统计及最大题量章节；
- `prerequisite_path`：返回常见主题的建议先修路径。

工具只读本地 JSON，不联网、不执行系统命令；返回数量受限，非法参数返回结构化错误。缺乏权威评分点的综合题不会被自动判分，避免伪造教师评分标准。

## 六、提示词与 RAG 优化

基线模型只有简短身份提示，主要问题是：不引用课程来源、资料缺失时猜测、无法真实抽题与批改、工具调用后可能停在占位文本。

优化内容包括：

- 课程事实仅依据本轮知识库或工具结果，禁止编造文件、页码和网址；
- 无依据时固定披露不确定性，并说明缺少何种资料；
- 讲义、实验和示例优先于历年试题；
- 按问答、分析、代码和批改任务使用不同回答结构；
- 作业题先给提示与关键步骤，不直接产出整份可提交答案；
- 抽题、判分和题库统计必须调用真实工具；
- 工具结果优先于一般拒答规则，工具返回错误时忠实报告错误与参数；
- `chapter_statistics` 直接返回 `max_chapter` 和 `max_count`，降低小模型二次比较出错的概率。

## 七、测试结果

### 7.1 Open WebUI 实际验收

2026-09-03 在本机原生部署上完成 15 项测试，结果为 **15/15 通过**：

- 知识问答 5/5；
- 综合分析 3/3；
- 资料缺失 2/2；
- 练习生成与批改 2/2；
- 工具调用 2/2；
- 异常输入 1/1。

每项均保存输入、AI 实际输出、Open WebUI `sources` 元数据、引用正确性、回答正确性、问题和改进建议，详见 `test-results/acceptance-test-report.md` 和机器可读的 `test-results/acceptance-results.json`。

其中两条实际回答采用了与检查词不同但语义等价的表达，例如“遍历找到”对应“查找/定位”，“请提供相关信息”对应拒绝在缺图时猜测。最终只放宽自动检查的同义表达，保留原始模型输出与来源不变，并由 `--reevaluate-existing` 复算结果，避免通过反复采样挑选答案。

### 7.2 优化前后对比

对 #2、#6、#9、#11、#12 使用相同输入和固定随机种子：

| 指标 | 基线模型 | 优化后课程模型 |
|---|---:|---:|
| 回答正确率 | 0/5 | 5/5 |
| 应引用用例的有效引用率 | 0/4 | 4/4 |
| 不确定性披露 | 0/1 | 1/1 |
| 工具任务成功 | 0/2 | 2/2 |

### 7.3 自动化回归

- 自动化单元测试：14/14 通过（13 项题库工具、1 项模型默认配置）；
- 数据校验：218 道题、28 份知识文件、4 类知识资料均通过；
- Python 语法、PowerShell 脚本语法和 Compose 配置均通过检查；
- 初始化脚本已在现有 Open WebUI 上重复执行，确认具有幂等性。
- 上下文回归：模型 `/props` 返回 `n_ctx=16384`、`total_slots=1`；实际 6201-token 请求成功完成，修复了旧配置 `8192 / 2 = 4096` 导致的 RAG 请求溢出。
- 交互延迟回归：关闭基础模型的通用隐藏工具注入后，浏览器等价“你好”请求从 6111 降至 30 prompt tokens，并在当前 CPU 后端由约 116 秒降至 0.76 秒；课程模型仍保留 RAG 与题库工具。

## 八、局限与后续改进

- 个别图形题只有文字转录，若题意依赖原图，系统会要求用户补图而不猜答案；后续可补充原始 PDF/题图并做 OCR 校对。
- 历年试题档案中保留了若干“以原图为准”的转录不确定项，因此 17 份真题不挂载到课程模型的默认核心 RAG；涉及精确题号时优先走结构化题库，存疑图题不自动给出权威结论。
- 3B 小模型资源占用低，适合本机演示，但复杂推理和工具调用措辞仍可能波动；有显存条件时可替换为更强模型并复跑同一验收集。
- 课程讲义是项目整理版，正式教学使用前仍应由任课教师审核术语和评分口径。
- GitHub 仓库已改为公开，可直接将仓库首页 URL 作为提交链接；仓库不包含模型、运行数据库、账号密码或 `.env`。

## 九、复现与运行

本机直接在项目根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\start-native.ps1
```

浏览器访问 <http://127.0.0.1:3000>，登录后选择“数据结构 AI 助教”。停止服务执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\stop-native.ps1
```

新机器的依赖下载、初始化、可选 Docker 方案和验收命令见 `docs/DEPLOYMENT.md`。
